# Training

## Preparing data

```bash
uv run tnsr data prepare                      # synthetic TinyTales corpus → datasets/demo (BPE, vocab ≤ 2048)
uv run tnsr data prepare --name demo-char --tokenizer char
uv run tnsr data prepare --name mydata --source ~/texts --vocab-size 8192   # your own .txt/.md files
uv run tnsr data inspect demo                 # statistics + a decoded validation sample
uv run tnsr data inspect ~/texts              # raw corpus statistics before preparing
uv run tnsr data list
```

Options: `--val-fraction` (default 0.05), `--seed` (split + generator), `--split-mode`
(`paragraph` splits files on blank lines, `file` treats each file as a document, `line` treats
each line as one). Existing datasets are never overwritten unless `--overwrite` is passed.

**Leakage protection.** Documents are assigned to train/val by hashing `seed:document`, so the
split is reproducible and order-independent, and duplicate documents always land together.
The tokenizer is fitted on the training split only; with the character tokenizer, characters
that appear only in validation map to `<|unk|>`.

**Licensing.** Only train on text you have the right to use. The bundled corpus is generated by
`tnsr_core/data/synthetic.py` and is MIT-licensed with the rest of the repository. User corpora
are recorded as `user-supplied` in `meta.json`.

## Presets

| preset | params | context | layers × d_model | intended for |
|---|---|---|---|---|
| `tiny` | ~80K | 32 | 2 × 32 | tests and smoke runs (seconds) |
| `demo` | 3.0M | 256 | 6 × 192 | the demonstration model on a laptop CPU (~30–40 min, 4 cores) |
| `char` | 0.8M | 256 | 4 × 128 | character-level comparison run (needs `demo-char` dataset) |
| `medium` | ~10.4M | 512 | 8 × 320, RoPE | Apple Silicon / CUDA; benefits from a larger corpus |

Presets live in `tnsr_core/config/presets/*.toml`. Any TOML file with the same sections works:
`uv run tnsr train --config my.toml`.

## Running

```bash
uv run tnsr train --config demo                       # new run in experiments/demo-<timestamp>
uv run tnsr train --config demo --name lr-sweep-1 --set train.learning_rate=1e-3 --set model.dropout=0.1
uv run tnsr train --config demo --smoke               # 20-step smoke test of the full pipeline
uv run tnsr train --config demo --device mps          # force a device (falls back to CPU if missing)
```

`--set section.key=value` takes TOML values. Unknown keys and wrong types are rejected before a
run directory is created. The model's `vocab_size` is always aligned to the dataset tokenizer.

Each log line reports loss, learning rate, gradient norm and tokens/second; every
`eval_interval` steps the train and validation loss are measured on fixed windows and a
checkpoint is saved. `keep_checkpoints` most recent checkpoints plus the best (lowest val loss)
are kept.

## Interrupting and resuming

`Ctrl+C` (or SIGTERM, or **Stop** in the Lab) finishes the current step, saves a checkpoint with
full optimizer and RNG state, marks the run `interrupted` and exits with status 130.

```bash
uv run tnsr train --resume demo-20261021-062619
uv run tnsr train --resume demo-20261021-062619 --max-steps 6000   # extend the budget
```

Resuming restores model weights, AdamW moments, the step counter, elapsed time and the Python,
NumPy, PyTorch and data-sampler RNG states, and truncates `metrics.jsonl` to the checkpoint's
step. An interrupted-then-resumed run is bit-identical to an uninterrupted one
(`tests/test_training.py::test_resume_is_exactly_equivalent_to_uninterrupted_training`).
Extending `max_steps` changes the cosine schedule from that point on. Resuming refuses to
continue if the dataset's content hash changed.

## Reliability features

- **Non-finite detection**: a NaN/Inf loss or gradient norm skips the update; after
  `max_nonfinite` consecutive bad steps the run fails with advice (lower LR, enable clipping,
  use fp32).
- **Gradient clipping** (`grad_clip`, 0 disables), **warmup + cosine/linear/constant decay**.
- **Mixed precision**: `precision = "auto"` uses bf16/fp16 autocast on CUDA and fp32 on CPU/MPS
  (CPU bf16 autocast is usually slower on consumer CPUs).
- **Reproducibility**: one `seed` drives initialisation, sampling and dropout; `run.json` stores
  the full config, PyTorch/Python versions, platform, device and git commit.

## Hardware notes

Measured on the development VM (4 x86 cores, no GPU, PyTorch 2.14 CPU): the 3.0M-parameter
`demo` preset trains at ~9–10K tokens/s when the machine is otherwise idle (4,096 tokens per
step). On Apple Silicon, `device = "auto"` selects MPS; set `PYTORCH_ENABLE_MPS_FALLBACK=1` if
an operation is unsupported on your macOS version. `tnsr doctor` runs a forward/backward smoke
test on the selected device.
